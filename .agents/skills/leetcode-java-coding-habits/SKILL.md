# LeetCode Java 刷题守则（学习策略 / IDEA 工作流 / Java 坑）

本用户是 Java + IDEA + 本地 LeetCode 仓库（按灵茶山艾府题单分类，`a<题号>.java` 命名）的刷题者。会话中会反复出现三类问题：①学习策略是否合理；②IDEA 本地编译 / JUnit 测试工作流；③实现细节与 Java API 报错。回答风格：紧凑直达（遵守省钱守则），先给结论再给理由，不展开长篇。

## 1. 学习策略问答（用户反复确认，直接肯定并给边界）

- 「想了一段时间没思路，直接看题解，验证/获得思路后再实现，合适吗？」→ 合适。给一个明确阈值：约 15–20 分钟无实质进展即可看题解；先看思路与复杂度分析，不急着看代码；理解后自己实现并 AC，以此验证理解。
- 「跳过专题中较难的进阶内容，直接进下一板块的简单部分，合适吗？」→ 合适，前提是该专题基础题已掌握。进阶内容标记待补，刷题是螺旋式推进，不必一题不漏、一步到位。
- 「实现时边界考虑不周、操作遗漏怎么办？」→ 编码前先列边界清单：空输入 / 单元素 / 最大最小值 / 负数 / int 溢出（必要时用 long）/ 索引 ±1 / 循环退出条件；每道题先想 2–3 个覆盖边界的用例再动手。总结（daily-summary）时把这类遗漏记进当次总结，积累个人易错清单。

## 2. IDEA 本地工作流

- 避免跨文件依赖（用户高频痛点）：LeetCode 提交要求单文件自包含。练习时就养成把辅助类（UnionFind、ListNode、TreeNode、工具函数）粘贴进同一文件（Java 同文件可有多个非 public 类），或从对应分类的 `_banzi.java` 模板复制，不要依赖同包其他文件——提交到 LeetCode 会编译失败。若用户想练工程化写法，提醒提交前必须内联。
- JUnit 本地测试总编译失败：IDEA 运行单个测试前会编译整个模块，任何其他文件/包的残留错误都会阻塞本次运行——这不是测试代码本身的问题。做法：先 Build 看全部报错，修完再跑测试；临时可注释掉有问题的文件。
- 运行单个测试编译、启动很慢：同上，IDEA 编译范围是整个模块。缓解：保持模块内所有文件可编译（无残留报错）、用增量构建、测试用 JUnit 跑而非 main 方法。

## 3. Java API 坑（记录用户实际踩过的）

- `StringBuilder` 没有 `isEmpty()`：`String` 有 `isEmpty()`，但 `StringBuilder` 的 `isEmpty()` 是 JDK 15 才新增（`CharSequence` 默认方法）。旧 JDK 下报「找不到方法」，用 `length() == 0` 判断。遇到「方法找不到」类报错，先确认目标类的 JDK 版本 API，再确认是否 import 了错误类型。
