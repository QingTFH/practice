# 刷题总结

> "本次刷的代码" = git 中尚未提交的部分（含已暂存/未暂存/未跟踪源码），与日期无关。

## 1. 统计与识别

执行两条 git 命令，收集数据：

1. 已跟踪题目集合 `$T`：
   ```powershell
   $T = git -c core.quotepath=false ls-files | Select-String -Pattern 'src/.*/a\d+\.java$'
   ```
2. 未提交变更 `$U`：
   ```powershell
   $U = git status --porcelain
   ```
3. **总计完成题数** = `$T.Count` + `$U` 中 `??` 未跟踪的 a 文件数。
4. **分类分布**：按 `$T` 的目录分组计数；`$U` 中未跟踪新增归入对应分类。
5. **静默写入**：总计与分类分布更新到工作区根目录 `刷题记录.md`（「总计已完成题数」+「分类分布」表格），报告中不输出分布表。
6. **本次题目清单**：从 `$U` 的 a 文件行（A/M/??）提取题号与分类；留意 `说明` 等非 `.java` 文件改动；必要时 `git diff` / `git diff --cached` 看具体改动。**`A`/`M`/`AM` 文件的工作区与暂存区内容可能不同：`git diff` 看工作区 vs 暂存区，`git diff --cached` 看暂存区 vs HEAD，两者都要查**；`AM` 且暂存区是空壳/占位时，工作区必有内容，以工作区（磁盘文件）为准。
7. **本次刷题数 x** = 清单去重题号数；无未提交变更时如实报告并询问是否仍要总结，不编造。

## 2. 识别未实现题目（写入未完成题目.md）

检测 `$U` 中"只看了题解、未独立实现"的题目，记入工作区根目录 `未完成题目.md`：

1. **检测对象**：`$U` 中文件名匹配 `a<题号>.java` 的文件（含 `random/`）；以及 `$U` 中修改过的**「说明」文档**（`src/` 下名为 `说明` 的无扩展名文件，每个分类目录下一个）。
2. **判定前必读本体**：必须用 read 工具读**磁盘工作区文件的实际内容**，不得仅凭 `git diff`/暂存区内容判定；`A`/`M`/`AM` 文件以工作区为准。
3. **判定"未实现"**（任一命中即记）：
   - 方法体为空：`方法名(...) { }` 内无有效语句/无 return；
   - 只 return 固定值：方法体仅一条 `return` + 固定字面量（`-1`/`0`/`null`/`""` 等），无计算逻辑；
   - **无实质性逻辑**：方法体内除注释、`return` 固定值外，无循环、条件分支、方法调用、变量运算等实质性语句；
   - 注释含标记：`未实现`、`没实现`、`直接看题解`、`看题解了`、`跳过`、`没写`；
   - **说明文档中标注"跳过"的章节**：`$U` 中修改过的「说明」文档里，含"跳过"的行即未完成章节（如 `跳过了 5.5 反悔堆、5.6 懒删除堆、5.7 对顶堆` → 记 `5.5 反悔堆`、`5.6 懒删除堆`、`5.7 对顶堆`）；
   - 用户口头点名。
4. **分类**：取 `src/` 下完整相对路径（如 `random`、`常用数据结构/字典树`）。
5. **写入**：分两个小节，**不写日期**，顺序为「跳过的章节」在前、「题号清单」在后，各自升序：
   - 跳过的章节：追加 `- <章节>（<分类>）` 到「跳过的章节」小节，**按章节号升序**（如 5.5 → 5.6 → 6.2），每个章节单独一行，**去重**；
   - 散落的题目：追加 `- <题号>（<分类>）` 到「题号清单」小节，**按题号升序**，每行一个，**去重**；
   - 未命中不改动。
6. 文档随第 5 步提交推送；有改动时在报告「本次题目清单」下注明。

## 3. 做法差距与代码优化

对第 1 步的「本次题目清单」中的每一题：

1. 用 read 工具读工作区文件本体，提炼算法/数据结构/复杂度/边界处理。
2. 审查该题代码：逻辑可简化（if 嵌套/冗余变量/重复计算/无用分支）、书写习惯（命名/注释/缩进空格/魔法数字）。**一律不修改代码**，只记录。
3. `web_search` 查题解（`LeetCode <题号> 题解`），**限次**：仅对「本次题目清单」中难度最高或代码最可疑的 **Top 3** 题搜索；其余题只做自省式逻辑审查，不搜索。

> 诚实对比，题解更优则明确承认，不牵强。

## 4. 提交并推送（自动，不询问）

1. 不提交 `.idea/`、`*.iml`、`src/out/`（由仓库 `.gitignore` 拦截）。
2. 设 `$env:GIT_SSH = "C:\Windows\System32\OpenSSH\ssh.exe"`。
3. `git add -A`。
4. 确认 `git status` 后提交，中文信息概括本次内容（题号 + 要点）。
5. `git fetch <remote> main`：远程有新提交则 `git rebase <remote>/main`；冲突则**终止并交用户手动处理**，不强行覆盖。
6. `git push <remote> main`（remote 以 `git remote -v` 为准）。
7. 验证 `git ls-remote <remote> main` 与 HEAD 一致。

## 5. 设置会话标题（自动，不询问）

将 dsh 会话标题改为 `yyyy-mm-dd 刷题数: x`（`x` = 第 1 步的「本次刷题数 x」）：

1. 按【skill:session-title】的「运行时重命名」操作。
2. `ctx.sessionTitle.rename(session, '<yyyy-mm-dd 刷题数: x>')`（`user` 来源钉住标题）。
3. 无现成工具则用 cordis 动态插件（define → run → stop）。
4. 不可用则提示用户手动重命名（UI 侧边栏），如实说明。

## 输出格式

报告标题 `# <yyyy-mm-dd>刷题总结`：

1. 总计完成题数（**仅数字**，分类分布已静默写入 `刷题记录.md`）
2. 本次题目清单（题号 + 分类 + 提交状态）
3. 每题差距分析（思路/复杂度/亮点/可改进点/代码优化建议）

**静默项**（正常时不输出，仅异常时报告）：
- 提交结果（hash、分支、远程确认）：正常静默；失败/不一致时输出问题。
- 会话标题设置结果：正常静默；未设置成功时提示用户手动重命名。

用户明确要求跳过某步则尊重；否则按默认执行，不额外询问。
